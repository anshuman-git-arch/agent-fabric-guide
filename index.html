MuleSoft Agent Fabric — Complete Guide to Multi-Agent AI Orchestration

MuleSoft Agent Fabric is the enterprise platform for building, orchestrating, and governing AI agent networks on Anypoint Platform. It combines Agent Brokers, Language Models (LLMs), MCP Servers, Specialist Agents, the Omni Gateway, and Anypoint Exchange into a cohesive production-ready system.

What is the Agent Broker?

The Agent Broker is the orchestrator in a MuleSoft Agent Fabric network. Defined as a .agent script file and deployed on CloudHub 2.0, it receives user requests, passes them to an LLM, reads tool-call decisions, and executes them — either calling an MCP tool directly or delegating to a specialist agent via the A2A (Agent-to-Agent) protocol.

How does the Language Model (LLM) work in Agent Fabric?

The LLM is the reasoning engine. The Broker feeds it the user's message and a list of available tools. The LLM returns tool-call instructions which the Broker executes. This loop repeats — tool results go back to the LLM — until the LLM composes a final answer. Agent Fabric supports any OpenAI-compatible endpoint: GPT, Claude, Amazon Bedrock, Azure OpenAI, and more.

What are MCP Servers in MuleSoft Agent Fabric?

MCP Servers implement the Model Context Protocol (MCP), an open standard by Anthropic. They wrap external APIs, databases, Salesforce, SAP, and other systems as structured tools with typed schemas. Any existing MuleSoft Mule application can be exposed as an MCP Server, making your existing integration assets immediately available as AI capabilities. Transport is via streamableHttp on CloudHub.

What are Specialist Agents in Agent Fabric?

Specialist Agents are autonomous sub-agents — each an expert in a narrow domain (Travel, Finance, HR, Search, etc.). The Agent Broker delegates tasks to them using the A2A (Agent-to-Agent) protocol developed by Google. Each specialist advertises its capabilities through an A2A card published to Anypoint Exchange. They can be deployed on CloudHub, on-premise, or as third-party services, and can run in parallel for complex workflows.

What is the Omni Gateway?

The Omni Gateway is a managed AI proxy that enforces enterprise policies on every LLM call in Agent Fabric. It provides authentication (Client ID, OAuth), rate limiting, token budgets per department or user, PII and content scanning, prompt injection detection, and full audit logging. It is managed via Anypoint API Manager using the same toolchain as your existing APIs.

How does Anypoint Exchange fit into Agent Fabric?

Anypoint Exchange is the universal registry for all Agent Fabric assets. Publishing an agent-network.yaml creates individually discoverable entries for the network, LLM providers, MCP servers, and agents. Teams across the organisation can discover, reuse, and govern AI assets through Exchange, with role-based access control and version management.

How does a request flow through MuleSoft Agent Fabric?

A user sends a request to the Broker's A2A endpoint. The Omni Gateway enforces policies. The Broker starts the agentic loop: it sends the message and available tools to the LLM. The LLM returns a tool-call instruction. The Broker executes the tool via MCP, injects the result back, and repeats until the LLM composes a final response. The response is streamed back and logged.

Why choose MuleSoft Agent Fabric over other AI agent frameworks?

MuleSoft Agent Fabric lets you reuse existing Mule integrations as MCP tools — no rebuilding. It provides enterprise-grade governance (auth, rate limiting, audit) built in from day one. It uses open protocols (MCP and A2A) that work with any LLM. It deploys on CloudHub 2.0, Runtime Fabric, or on-premise. Full observability through Anypoint Monitoring with token usage, latency, and cost attribution dashboards.

Core Component

Agent Broker

The Broker is the brain of the network. It receives the user's request, hands it to the LLM for reasoning, reads the LLM's tool-call decisions, and executes them — either calling an MCP tool directly or delegating to a specialist agent via A2A.

  • Defined as a .agent script file — a simple, declarative instruction set you write
  • Runs inside a MuleSoft runtime on CloudHub 2.0
  • Maintains conversation context across multi-turn interactions
  • Communicates with sub-agents over A2A (Agent-to-Agent) protocol
  • Each broker exposes an A2A card — its public skill manifest for discovery
  • Can run multiple brokers in one network for complex, parallel workflows

Core Component

Language Model

The LLM is the reasoning engine. It doesn't know about agents or tools directly — the Broker feeds it the user's message plus a list of available tools, and the LLM decides what to do next: answer directly, or call a tool.

  • Supports any OpenAI-compatible endpoint — GPT, Claude, Bedrock, Mistral
  • Registered in agent-network.yaml as an llm in the registry
  • Connected via API key authentication (stored as secure CloudHub property)
  • Returns tool-call instructions which the Broker executes
  • Runs iteratively — tool results go back to LLM until it signals completion
  • Azure OpenAI: add Azure OpenAI Transcoding policy in API Manager

Specialist Agents

While the Broker handles orchestration, Specialist Agents are autonomous sub-agents — each one an expert in a narrow domain. The Broker delegates to them like a manager assigning tasks to team members.

  • Each specialist is a fully independent agent — its own LLM, its own tools
  • Communication uses the A2A (Agent-to-Agent) open protocol from Google
  • Each agent advertises its skill manifest (A2A card) so the Broker knows what it can do
  • Can be deployed anywhere — CloudHub, on-premise, third-party
  • Examples: Travel Agent, HR Compliance Agent, Fraud Detection Agent
  • Enables parallel execution — multiple agents working simultaneously

MCP Servers

MCP (Model Context Protocol) is the standard way AI agents call external tools. An MCP Server wraps any API, database, or system — turning it into a structured tool an LLM can call by name with typed parameters.

  • Open standard by Anthropic — works with any LLM
  • Transport: streamableHttp (deployed on CloudHub) or stdio (local)
  • Each tool has a typed schema — the LLM knows exactly what to pass
  • Tools: REST APIs, Salesforce, SAP, databases, file systems, web search
  • A MuleSoft Mule app can expose itself as an MCP Server — reuse existing integrations
  • Registered in agent-network.yaml under mcps:

Omni Gateway

Every LLM call in Agent Fabric flows through the Omni Gateway — a managed AI proxy that enforces enterprise policies before any token reaches the model. Think of it as a security checkpoint with intelligence.

  • Intercepts every request and response between broker and LLM
  • Enforces rate limiting per user, tenant, or API key
  • Applies content filters — blocks PII, prompt injection, toxic content
  • Full audit trail — every prompt and response is logged and traceable
  • Supports token budgets — cap spend per department or user
  • Managed via Anypoint API Manager — same toolchain as your other APIs

Exchange & Monitoring

Anypoint Exchange is the universal registry — every agent, MCP server, LLM, and broker is published here. It's how teams discover, reuse, and govern AI assets across the organisation.

  • Publish your agent-network.yaml to Exchange as a single versioned asset
  • All sub-assets (LLM, MCP, agents) get their own Exchange entries — independently discoverable
  • Anypoint Monitoring: real-time dashboards for token usage, latency, errors
  • Audit logs, tracing, and alerts built in — no extra instrumentation needed
  • Role-based access control — control who can consume which agents
